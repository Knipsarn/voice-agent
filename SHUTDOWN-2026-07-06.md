## REACTIVATION RUNBOOK

Everything is data + config; nothing was lost. To bring the platform back:

1. **Recreate secrets** (Secret Manager, project `ldk-clean`) — all 20 names above.
   Generate fresh keys at each provider (old ones should be treated as rotated).
   Use `printf '%s' "$KEY" | gcloud secrets create NAME --data-file=-` — never `echo` (CRLF bug, see CLAUDE.md §10).
2. **Fortnox**: the OAuth refresh token in `fortnox_auth/tokens` expires ~45 days after
   2026-07-06. After that, re-run the OAuth connect flow (`scripts/ops/fortnox-connect.js`)
   with a valid Integrationspaket.
3. **Re-enable the 4 Cloud Build triggers** (they are disabled, not deleted):
   `gcloud builds triggers list` → PATCH `disabled=false` (or console toggle).
4. **Deploy**: push any commit to `main` (or `gcloud builds submit` per cloudbuild yaml).
   Builds push to `gcr.io/ldk-clean/*` — the `gcr.io` repo auto-creates on first push
   (createOnPush). If it doesn't: `gcloud artifacts repositories create gcr.io --repository-format=docker --location=us --project ldk-clean`.
5. **Recreate the 4 Cloud Scheduler jobs** — definitions in `infrastructure/setup.sh`.
6. **Telephony**: if the Telnyx numbers were kept, they are still attached to Call Control
   App `voice-platform-shared` (ID `2946878804032751101`) pointing at the telephony-service
   URL — verify the webhook URL after redeploy (URL should be identical:
   same project number + region). If numbers were released, buy new ones and update
   Firestore `phone_numbers/<e164>` + tenant configs.
7. **Verify**: `node scripts/ops/health.js`, then a test call.

Firestore is untouched, so tenants/configs/history work immediately on redeploy.
